# 선두 경로 입력 만료 시 정지 대기와 복구

## 변경

Nav2 follow-only 자동 Goal 모드에서 원격 선두/경로 입력이 일시적으로
만료되면 프로그램을 즉시 종료하는 대신 STOP_FOLLOW_REFERENCE_WAIT 상태로
영속도 명령을 보낸다. 기존 선두 gate는 STOP_ 상태를 받으면 영속도를 출력한다.
선두 gate와 모터 드라이버 코드는 이번 변경에서 수정하지 않았다.

정지 명령은 계속 유효한 후발 지도 위치와 라이다 측정 시각을 사용한다.
오래된 선두/경로 시각을 현재 시각으로 바꾸거나, 오래된 경로로 주행하지 않는다.
로컬 위치/라이다가 유효하지 않으면 기존 종료 처리를 따른다.

복구 조건:

- 선두·경로·후발 위치·라이다가 기존 신선도/형상 검사를 통과한다.
- 1초간 연속 유효하고 각 입력에서 서로 다른 시각 3개 이상을 확인한다.
- 드라이버가 같은 arm 세션에서 오류 없이 신선한 피드백을 제공한다.
- 양쪽 보고 RPM 0과 영속도 피드백 3회 이상을 확인한다.
- 같은 실행에서 Goal이 계속 활성 상태여야 한다.

복구해도 새 arm을 요청하지 않는다. 최대 대기 시간은 첫 손실부터 10초이며,
반복 손실로 기한을 연장하지 않는다. 초과하면 FOLLOW_REFERENCE_RECOVERY_TIMEOUT으로
종료한다. 전체 시험 시간도 기존처럼 계속 흐른다.
Goal 종료, 모터 오류, 로컬 센서 오류와 경로 추적 오류의 종료 처리는 유지한다.
인코더 보고 영속도는 독립적인 물리적 정지 확인이 아니다.

종료 보고에 reference_recovery_waits와 reference_recovery_timeout_s를 추가했다.

## 검증

reference_recovery_regression.log: 관련 검사 108개 통과.
실제 제어 흐름을 가짜 ROS/시계로 실행해 DRIVE → 원격 경로 만료 → STOP만 송신
→ 새 입력 1초 검증 → DRIVE 재개와 arm 1회 유지를 확인했다.
반복된 같은 시각으로 복구하지 않는 조건, 10초 만료, Goal 종료와 모터 오류 시
재개 금지, 기존 gate의 STOP 처리도 검사했다. 실제 로봇은 실행하지 않았다.

보호 백업 818개 파일은 변경이 없다. 변경 전 실행 파일:
run_local_avoidance_trial.before_reference_wait.py.

## 적용

후발 추종 프로그램만 종료 후 같은 명령으로 재실행한다. 이전 Goal을 먼저
취소하고, 입력 준비가 끝난 뒤 새 Goal을 지정한다. 이번 수정 때문에 모터
드라이버·센서·AMCL·Bridge·선두 Nav2를 재시작할 필요는 없다.

표시:

```
[FOLLOW] STOP: 입력 갱신 대기. 새 입력 검증 후 자동 재개합니다.
[FOLLOW] 입력 갱신·정지 피드백 확인. 추종을 재개합니다.
```
