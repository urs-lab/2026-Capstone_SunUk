# 급회전 사고 명령 경로 검토

실제 모터 구동, 포트 열기, 설정 쓰기 없이 저장 로그와 후보 드라이버의 실제
RPM 변환·패킷 생성 함수를 검사했다. 운용 코드 변경은 하지 않았다.

## 확인한 결과

- 사고 로그의 local_control 62개를 변환하면 모두 좌우 바퀴가 같은 크기의
  전진 RPM이다. 원시 M1 음수/M2 양수는 현재 설정에서 전진 방향이다.
- 최대 계산 명령과 저장된 sent_rpm의 최대 크기는 모두 4RPM이다.
- 명령 각속도를 시간 적분하면 약 -0.036도, 정수 RPM 변환 후 이상적인
  바퀴 추종을 가정한 각도는 0도이다. 저장 명령만으로 급회전을 설명할 수 없다.
- 반면 지도 위치 추정의 방향 변화는 첫 알람 관측 전까지 약 38.22도,
  정지 요청 이후를 포함한 로그 끝까지 약 57.26도였다. 지도 추정은 독립적인
  실측이 아니며, 실제 주행 속도나 물리적 정지를 증명하지 않는다.
- 허용 전진 범위의 명령 128,281쌍을 검사해 RPM 부호·10RPM 상한·패킷
  복원·체크섬 불일치는 발견되지 않았다. 유한 격자 검사이며 모든 입력의 증명은 아니다.
- 메모리 통신으로 주행 중 M2 알람 프레임을 주입했을 때 영속도를 송신하고,
  이후에도 비영속도를 보내지 않으며 외부 드라이버 계약의 재arm이 거부됐다.

## 해결 여부

이전에 발견한 간격 1.51m에서의 출발/정지 반복과 이번 급회전은 구분한다.
최소 속도 후보로 앞의 반복을 없앤 결과가 엔코더 알람이나 급회전 해결을
뜻하지는 않는다. 속도 하한 후보는 기본 비활성화 상태로 유지한다.

저장된 제어·상태 샘플은 연속적인 실제 직렬 전송 기록이 아니다. 미기록 명령,
실제 수신 패킷, 드라이버 내부 제어 반응, 위치 추정 오류, 센서 문제는 아직
분리되지 않았다. 따라서 소프트웨어 또는 케이블 어느 한쪽을 원인으로 단정하지 않는다.

다음 실제 검증은 지상 Goal 재실행이 아니라, 물리적 이동을 억제한 조건에서
직렬 송신·수신과 독립적인 바퀴 반응을 함께 관측하는 단계가 필요하다.
현재 도구 환경에서는 실제 로봇 프로세스와 시리얼 포트에 접근해 이를 수행하지 않았다.
엔코더 알람 보호와 기존 백업을 유지한다.
